4. SYSTEM ARCHITECTURE

4.1 Architecture Overview

FloraLens is constructed upon an enterprise-grade, three-tier decoupled client-server architecture designed for high availability, fault tolerance, and modular extensibility. The system decouples the presentation interface from the business logic and persistence tiers, communicating over standardized HTTPS/JSON REST protocols.

Figure 1: High-Level Three-Tier System Architecture and Request Pipeline

4.2 Layers of the Architecture

1. Presentation Tier (Client): Implemented as a Single Page Application (SPA) using React 19 and TypeScript. It compiles into static HTML/CSS/JS bundles delivered via Vite. The presentation tier manages local UI state, routes client views, and renders responsive cards, forms, and modals.

2. Application Tier (Server): Powered by Node.js and the Express 5 framework. It encapsulates business logic, including input sanitization, stock decrements, coupon discount math, and calendar slot collision validation algorithms.

3. Persistence Tier (Database): Hosted on a distributed MongoDB Atlas M0 replica set cluster (floralens), offering JSON document storage across ten collections with automated index lookups and connection pooling.
