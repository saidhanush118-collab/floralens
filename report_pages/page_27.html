6.7 Authentication and Role-Based Authorization

FloraLens implements a multi-tier authentication engine supporting email/password registration, Google OAuth simulation, and persistent session storage. The system enforces strict access policies:

• Public Routes: Homepage, Catalog, Product Details, Vendor Showcase, About, FAQ, Privacy, Terms.

• Customer Routes (/customer/*): Restricted to registered shoppers; permits address management, wishlist operations, and personal order tracking.

• Vendor Routes (/vendor/*): Restricted to accounts with vendor role; permits order stage progression, inventory updates, and booking acceptance.

• Admin Routes (/admin/*): Restricted to admin accounts; permits vendor KYC verification and transaction audit.

6.8 Product Catalog and Multi-Tier Variant Pricing Logic

To model realistic florist operations, each flower product defines a base price and an array of variants. For example, a "Crimson Rose Bouquet" provides:

• Standard Tier: 12 Stems (Base Price, e.g., ₹799)

• Deluxe Tier: 24 Stems (Base Price × 1.40, e.g., ₹1,119)

• Premium Tier: 36 Stems (Base Price × 1.88, e.g., ₹1,499)

6.9 Event Decoration Booking Logic and Double-Booking Prevention

The double-booking prevention engine constitutes a primary technical innovation of FloraLens. When a customer submits a booking request for a decorator on a specific eventDate and timeSlot, the Express route executes a deterministic query against MongoDB Atlas:

const existingConflict = await db.collection('bookings').findOne({ vendorId: req.body.vendorId, eventDate: req.body.eventDate, timeSlot: req.body.timeSlot, status: { $in: ['confirmed', 'accepted_by_vendor', 'preparing'] } }); if (existingConflict) { return res.status(409).json({ success: false, error: 'Double-Booking Conflict: Slot already reserved.' }); }

If an existing active booking matches the tuple (vendorId, eventDate, timeSlot), the API returns HTTP 409 Conflict, safeguarding the decorator's schedule integrity.
