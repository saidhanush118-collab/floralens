4.5 Multi-Role Ecosystem and Access Control

FloraLens implements a sophisticated Role-Based Access Control (RBAC) model governing three distinct user personas:

1. Customer Portal: Accessible to registered users and authenticated shoppers. Capabilities include browsing flower and decoration catalogs, selecting bouquet tiers, configuring event packages and add-ons, managing saved delivery addresses, placing orders, and monitoring visual order progression timelines.

2. Vendor Portal: Restricted to verified florists and decorators. Provides a dedicated management console where vendors inspect active orders, advance fulfillment stages (Pending ➔ Confirmed ➔ Preparing ➔ Dispatched ➔ Delivered), accept or decline decoration bookings, manage item prices and stem quantities, and configure availability calendars.

3. Platform Administrator Portal: Restricted to platform managers. Provides governance capabilities including reviewing vendor KYC applications, verifying GSTIN credentials, moderating product and service listings, and auditing aggregate platform transactions.

4.6 System Workflow and Request Pipeline

Every user interaction follows a deterministic request-response flow:

• Action Initiation: A customer interacts with a UI component (e.g., clicking "Add to Cart" or "Book Decoration Slot").

• Context Synchronization: The action triggers a method in StoreContext, which immediately validates client constraints (e.g., minimum order quantity, variant existence).

• REST API Invocation: The client issues an asynchronous HTTP request via fetch to /api/orders or /api/bookings.

• Server Validation & Collision Checks: Express route controllers verify payload schema, decrement stock atomically, and execute MongoDB queries to ensure no conflicting confirmed booking exists for that vendor and time slot.

• Database Mutation: Upon successful validation, documents are committed to MongoDB Atlas, and a standardized JSON envelope ({ success: true, data: ... }) is returned to update the client state and UI.
