ABSTRACT

FloraLens is a full-stack, cloud-connected digital marketplace and event-service booking engine engineered specifically for the Indian floral retail and event styling sector. Traditional floral commerce platforms in India suffer from fragmented local vendor management, lack of real-time inventory synchronisation, opaque pricing, and the total absence of a combined solution for both retail flower delivery and on-site event decoration booking (such as weddings, birthdays, anniversaries, and pooja arrangements).

FloraLens addresses these operational bottlenecks through a decoupled, modern multi-tier architecture. The frontend is built using React 19, TypeScript, and Tailwind CSS, featuring an intuitive luxury design, dynamic occasion catalogs, real-time cart calculations, and role-based views. The backend is implemented with Node.js and Express 5, interfacing with a managed MongoDB Atlas database cluster across ten core collections: categories, vendors, products, services, orders, bookings, reviews, coupons, addresses, and users.

The system computes dynamic tiered variant pricing, manages inventory decrements, and enforces a strict slot collision algorithm that prevents conflicting decorator bookings for identical event dates and time intervals. A multi-stage order tracking pipeline provides live visibility into delivery progression from order placement through confirmation, preparation, dispatch, and doorstep delivery. Furthermore, FloraLens integrates Indian Rupee (₹ INR) localization, Indian address formats, and Razorpay Sandbox payment simulation.

Importantly, the system achieves these capabilities natively in code without relying on external automation tools (n8n) or third-party AI wrappers. The architecture is structured to support high-value interactive extensions: an Interactive DIY Bouquet & Gift Studio, a Digital Video/Voice Greeting QR Card Engine, BloomBox Flower Subscriptions, a Smart Occasion Vault, Milestone Escrow Payments for Decorators, and a Venue Decor Palette Visualizer. The prototype is fully bench-tested, demonstrating a responsive and scalable platform for modern floral commerce.

1. INTRODUCTION

The floral retail and event decoration market in India represents a unique blend of cultural tradition and rapid digital commerce growth. Fresh flowers hold essential ceremonial, religious, and emotional importance across daily household poojas, milestone birthdays, corporate inaugurations, and multi-day weddings. Despite sustained customer demand, the existing digital ecosystem remains deeply fragmented. Customers either purchase standardized, overpriced flower bouquets from closed corporate aggregators or rely on unorganized phone calls and physical market visits to arrange local event decorators.

Our project, FloraLens, is a full-stack e-commerce marketplace and event service booking platform engineered to unite local florists, professional event decorators, and retail customers on a single, transparent digital hub. Built using React 19, TypeScript, Node.js, Express 5, and MongoDB Atlas, FloraLens provides an end-to-end commercial pipeline that handles both perishable retail goods and scheduled on-site decor services.

The system is needed because small-scale florists and independent decorators lack the technological tools to manage dynamic inventories, prevent double-bookings during festive peak seasons, and offer transparent pricing. Customers, on the other hand, struggle with opaque event packages, uncertain delivery timelines, and lack of customization. FloraLens demonstrates how modern full-stack engineering can deliver an accessible, luxury commercial experience with native transactional safeguards.

The scope of this project is a functional, bench-tested prototype featuring full database connectivity to MongoDB Atlas, verified order calculations, and simulated payment processing via Razorpay Sandbox. It is designed around three distinct user roles: Customers, Vendors (Florists & Decorators), and Platform Administrators, linked through role-based access route guards and persistent authentication.

2. LITERATURE REVIEW

2.1 Background study

Modern electronic commerce has evolved significantly from early static server-rendered catalogs to asynchronous, client-side single-page applications (SPAs) supported by microservices or REST API gateways. In the floral and gifting domain, early platforms relied on rigid relational schemas that struggled to capture the polymorphic nature of floral products (stem counts, sizes, wrapping types) and event decoration packages (time slots, guest counts, venue specifications, add-on accessories).

Existing commercial players in the Indian market include gifting platforms such as Ferns N Petals (FNP) and Interflora, alongside on-demand home service aggregators like Urban Company. However, these services operate in distinct silos: gifting portals focus solely on standardized boxed deliveries without addressing custom venue decoration, while home-service portals treat decoration as an occasional cleaning or repair add-on without catering to the bespoke artistic requirements of Indian celebrations.

Furthermore, managing floral products requires addressing stem perishability (with shelf lives ranging from 24 to 72 hours) and preventing inventory overselling. In event decoration, the core operational challenge is temporal scheduling: an individual decorator cannot physically execute two major wedding stage setups at 6:00 PM on the same festival date in different venues. Relational systems manage this via strict table locks, whereas modern document databases such as MongoDB handle this through compound indexes and atomic query assertions.

React 19 with TypeScript provides compile-time type safety, rapid component re-rendering via virtual DOM reconciliation, and clean separation between view and state logic. Express 5 provides an asynchronous, non-blocking I/O runtime well-suited for high-concurrency e-commerce traffic, and MongoDB Atlas offers high availability, schema flexibility, and managed connection pooling.

4. SYSTEM ARCHITECTURE

4.1 Architecture overview

FloraLens follows a decoupled four-stage processing pipeline: Client Request, API Routing & Validation, Database Persistence, and Fulfillment Tracking. The web client renders UI components and captures user intent; the Express server validates payloads, enforces business rules, and performs slot collision queries; MongoDB Atlas persists transactional documents; and the vendor portal manages live order fulfillment.

Figure 1: System architecture and processing pipeline

4.2 Layers of the architecture

The architecture comprises four distinct layers:

  • Presentation Layer: React 19 single-page application utilizing Tailwind CSS, Lucide React icons, and Context API for global store and authentication state.
  • Routing & Access Control Layer: React Router v7 with role-based route guards (<ProtectedRoute>) restricting views to Customers, Vendors, or Admins.
  • Application / Server Layer: Node.js and Express 5 REST API providing endpoints for products, services, bookings, orders, and PBKDF2 password authentication.
  • Persistence Layer: Managed MongoDB Atlas database cluster maintaining ten collections with connection caching and schema validation.

6. METHODOLOGY

6.1 Development approach

FloraLens was engineered using an iterative, component-driven full-stack development lifecycle. We first defined domain entities, database schemas, and double-booking collision rules. We then built the Node.js/Express API server, seeded authentic mock data across ten MongoDB collections, implemented salted PBKDF2 authentication, and created the React 19 single-page application.

6.2 Working of the system

When a customer selects a floral product, the client dynamically recalculates pricing based on chosen variants (Standard, Deluxe, Premium). When reserving an event decorator, the user selects an event date and a four-hour time slot. The Express backend queries MongoDB to verify if that vendor already has an active booking (status confirmed or in_progress). If so, an HTTP 409 Conflict is returned; otherwise, the slot is reserved. The checkout flow applies coupon discounts, adds delivery fees if below ₹999, and executes sandbox payment simulation.

6.3 Frontend and backend

The frontend is an optimized SPA built with React 19 and Tailwind CSS. State is managed via StoreContext (cart, search filters, and catalog cache) and AuthContext (credentials, roles, and session persistence). The backend is an Express 5 server featuring MongoDB connection pooling and cryptographic password hashing.

Table 4: Formulas and parameters
Quantity Formula Notes
Variant Price Price = BasePrice * Multiplier Deluxe = 1.4x, Premium = 1.8x.
Order Subtotal S = Sum(UnitPrice * Quantity) Aggregates cart line items.
Coupon Discount Discount = S * (Rate / 100) BLOOM10 = 10% discount.
Delivery Fee Fee = (S >= 999) ? 0 : 50 Free shipping threshold at ₹999.
Slot Collision Count(vendor, date, slot, active) > 0 Prevents decorator double-booking.
Vendor Payout Payout = Subtotal * 0.90 Reflects 10% platform fee.

6.5 Data handling and alert logic

Customer orders are isolated by customerId to prevent cross-account exposure. Password hashes are generated using 1000 iterations of PBKDF2 with SHA-512 and unique salts. Slot collisions return descriptive conflict messages advising users to select alternate dates or slots.

6.6 Testing approach

Testing followed a four-tiered strategy: automated Vitest unit tests for cart and store math (5/5 passing), React Testing Library component tests (3/3 passing), REST API integration tests, and simulated multi-role user walkthroughs.

7.3 Worked example

Example 1: Cart Calculation with Deluxe Variant and Coupon
Suppose a customer orders 2 units of the Crimson Rose Bouquet (Base Price ₹799) with Deluxe tier (1.4x multiplier):
• Unit price = 799 × 1.4 = ₹1,118.60 (rounded to ₹1,119).
• Line item subtotal = 1,119 × 2 = ₹2,238.
• Apply BLOOM10 coupon (10% discount): Discount = 2,238 × 0.10 = ₹223.80.
• Delivery fee: Subtotal ≥ ₹999, so delivery fee = ₹0.00.
• Final Total = 2,238 − 223.80 + 0 = ₹2,014.20.

Example 2: Event Decoration Double-Booking Collision
Vendor v_royal_decors is booked for "Wedding Stage" on 2026-12-15 from 16:00 - 20:00. If another customer requests the same slot, findOne() detects the conflict and rejects the booking with an HTTP 409 status code.

9. CONCLUSION AND FUTURE SCOPE

9.1 Conclusion

The FloraLens field project demonstrates how modern full-stack engineering, resilient REST API design, and distributed cloud document storage can be harmonized to solve real-world logistical, scheduling, and commercial challenges in the Indian floral retail and event styling industry. By pairing React 19, TypeScript, and Tailwind CSS on the frontend with Node.js, Express 5, and MongoDB Atlas on the backend, the platform delivers an accessible, high-performance, and luxury marketplace experience.

The system successfully eliminates double-booking hazards through deterministic database collision checks, safeguards inventory with variant-aware stock management, provides end-to-end transparency via multi-stage order tracking, and supports multi-role administrative oversight. Most importantly, the platform achieves these milestones natively in code, ensuring high reliability, zero external SaaS dependencies, and full intellectual property ownership.

9.2 Future Scope (Extended Native Features Roadmap)

Building upon the robust full-stack foundation established in this report, the following high-value native features represent the roadmap for FloraLens. Each feature is designed to run natively within our existing React, Express, and MongoDB stack without requiring external automation tools (e.g., n8n) or third-party AI services:

  1. Interactive DIY Bouquet & Gift Studio: A client-side visual studio allowing users to customize bouquet wrap styles (Kraft paper, Luxury Velvet, Woven Basket), select primary stem counts (Dutch Roses, Asiatic Lilies), choose fillers (Baby's Breath, Eucalyptus), and add treats (Chocolates, Personalized Card, Teddy), dynamically calculating pricing into the cart.
  2. Digital Video / Voice Greeting QR Card Engine: Allows customers to attach a personalized video/voice message at checkout (+₹49). The server generates a unique QR code printed on the physical bouquet card. The recipient scans the QR code to view a personalized multimedia greeting page (/greeting/:id).
  3. "BloomBox" Flower Subscriptions (Pooja, Home & Office): A native recurring order engine supporting Daily Fresh Pooja Flowers (Marigold, Jasmine), Weekly Home Decor Blooms, and Corporate Office arrangements with pause/skip controls.
  4. Smart Occasion Vault & Automated Reminders: Customer calendar storing birthdays and anniversaries, providing dynamic dashboard reminder banners and 1-click repeat gifting.
  5. Milestone Escrow Payments for Decorators: Three-stage payment protection for high-ticket decor contracts: Stage 1 (30% booking advance), Stage 2 (50% on-site decorator check-in), and Stage 3 (20% post-event satisfaction sign-off).
  6. Venue Decor Palette & Theme Visualizer: Interactive room and theme configurator allowing customers to preview color schemes (Pastel Bloom, Royal Marigold, Boho Chic) on stages, mandaps, and backdrops with itemized cost estimation.
  7. Farm-to-Vase Freshness Badge & Supply Chain Origin Tracking: Dynamic badges displaying harvest timestamps and farm origin (e.g., Ooty, Bengaluru flower farms) to assure freshness.
